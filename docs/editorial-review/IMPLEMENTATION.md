## Live acceptance finding: public proxy origins

The first public-domain browser plan failed. A direct request with `Origin: https://netify.co.uk` reproduced HTTP 403, `Origin not allowed`. This guard compared the browser origin only to the rewritten SASE request URL. The same guard existed in the preceding release and across nine sourcing routes. A live Neon dataset alone had not proved the interactive journey.

The corrective patch accepts exact Netify production origins and configured deployment hosts, with no forwarded-host or wildcard-domain trust. Authentication, recipient consent, payload validation and work-email confirmation remain required. Circuit routes already had their own public-origin handling and were left unchanged. Tests cover lookalike origins, spoofed forwarded hosts, preview separation and a complete captured-mail request/confirmation/auth recovery journey using different public and backend origins. Full action-first regression, TypeScript, focused lint and production build passed. GitHub CI now also executes these proxy-origin and route tests. Public-domain functional retest is required after the patch deployment.
