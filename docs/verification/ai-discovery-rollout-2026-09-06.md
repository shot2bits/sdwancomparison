# Six-step AI discovery rollout

User-authorized sequential implementation. Each step is checked locally, deployed as a production candidate without domain promotion, tested, then promoted and tested through netify.co.uk before the next step.

1. Discovery: canonicals, sitemap, public navigation, redirect hops, truthful optional-RFP messaging.
2. Existing research to project: preserve entry pages and carry buyer-chosen context into the canonical workspace.
3. Demonstration: labelled manufacturing example showing requirements, supplier questions, notice and response comparison; all document depths retained.
4. Pricing: distinguish provisional budgeting, supplier project responses and sourced circuit quotes.
5. MCP: align public capability descriptions, evidence URLs, continuation and permission boundaries; test actual public tools.
6. Outcomes: privacy-safe route attribution and server-confirmed publication/response measurement; an authenticated reporting view and baseline plan.

Tests must not send real emails, publish fictional opportunities or pollute live buyer data. Browser form writes are intercepted; store/authorization tests use fake KV. Live HTTP, rendered UI, public MCP reads and authentication denial checks use actual production routes.
